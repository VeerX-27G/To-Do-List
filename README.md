# To-Do List

A simple to-do list app with a REST API backend built on **FastAPI** and **SQLAlchemy** (SQLite), and a lightweight HTML, CSS and JavaScript frontend served by the same app.

> The frontend was made with GenAI tools. The backend was written by me.

## Features

- Add, list, update (mark done / undo) and delete to-dos
- REST API with request and response validation through Pydantic
- Data stored in a local SQLite database, created automatically on first run
- Interactive API documentation generated by FastAPI
- Single process: the API and the web page are served together from one app

## Tech stack

| Layer | Tools |
| --- | --- |
| API | Python, FastAPI |
| Database / ORM | SQLite, SQLAlchemy |
| Validation | Pydantic |
| Frontend | HTML, CSS, vanilla JavaScript |

## Project structure

```
To-Do-List/
├── main.py          # FastAPI app: CRUD routes, CORS, static file serving
├── database.py      # SQLAlchemy engine, session factory and Base
├── models.py        # Todo table definition (ORM model)
├── schemas.py       # Pydantic schemas for request and response bodies
├── tables.py        # Standalone copy of the Todo model definition
├── static/
│   ├── index.html   # Page markup
│   ├── script.js    # Calls the API and renders the list
│   └── style.css    # Styling
└── todos.db         # SQLite database file
```

## Getting started

### Prerequisites

- Python 3.9 or newer

### Installation

```bash
git clone https://github.com/VeerX-27G/To-Do-List.git
cd To-Do-List

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install fastapi uvicorn sqlalchemy
```

### Run it

Start the server from the project root, because the static folder and database path are relative:

```bash
uvicorn main:app --reload
```

Then open:

- App: <http://127.0.0.1:8000>
- Interactive API docs (Swagger UI): <http://127.0.0.1:8000/docs>

The `todos` table is created automatically the first time the app starts.

## API reference

| Method | Endpoint | Description |
| --- | --- | --- |
| `POST` | `/todos/` | Create a to-do |
| `GET` | `/todos/` | List all to-dos |
| `GET` | `/todos/{todo_id}` | Get a single to-do |
| `PUT` | `/todos/{todo_id}` | Update a to-do's title and completed status |
| `DELETE` | `/todos/{todo_id}` | Delete a to-do |

Requests that reference an id that doesn't exist return `404` with `{"detail": "Todo not found"}`.

### Data model

Request body for `POST` and `PUT`:

```json
{
  "title": "Buy groceries",
  "completed": false
}
```

Response body:

```json
{
  "id": 1,
  "title": "Buy groceries",
  "completed": false
}
```

`completed` is optional and defaults to `false`.

### Example

```bash
# Create
curl -X POST http://127.0.0.1:8000/todos/ \
  -H "Content-Type: application/json" \
  -d '{"title": "Buy groceries"}'

# List
curl http://127.0.0.1:8000/todos/

# Mark as done
curl -X PUT http://127.0.0.1:8000/todos/1 \
  -H "Content-Type: application/json" \
  -d '{"title": "Buy groceries", "completed": true}'

# Delete
curl -X DELETE http://127.0.0.1:8000/todos/1
```

## How it works

- `database.py` sets up a SQLite connection (`todos.db` in the working directory) and a session factory.
- `main.py` provides a `get_db` dependency that opens a session per request and closes it afterwards.
- CORS is open to all origins, which is convenient for development.
- The `static` folder is mounted at `/` as the last route, so the frontend is served from the root URL and the `/todos/` API routes keep priority.
